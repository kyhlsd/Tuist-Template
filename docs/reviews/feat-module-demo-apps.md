## 확정 결정

| # | 결정 | 이유 |
| --- | --- | --- |
| R-D1 | PersistenceDemo 는 `.onDisk` 실패 에러를 모델의 `onDiskError` 로 넘겨 화면에 보여 준다. `.inMemory` 까지 실패하면 `DemoStoreOpenFailure` 로 두 에러를 함께 보여 준다 (R1-1) | 폴백한 이유를 버리지 않는다(에러 삼킴 금지). `isInMemoryFallback: Bool` 대신 에러 하나로 폴백 여부와 원인을 함께 나타낸다 |
| R-D2 | 데모 모델의 `lastError` 는 사용자 동작(버튼·Picker)을 시작할 때만 비운다. 화면 진입 로드, 동작 뒤 목록 재조회(`reload()`), Auth 상태 알림에 따른 토큰 재조회는 비우지 않는다. PersistenceDemo 의 화면 진입은 `.task { reload() }` 다 (R1-2, R2-1) | 화면의 에러가 마지막 동작의 것이 되게 한다. 사용자 동작이 아닌 경로가 비우면 앞선 에러(뷰가 뜨기 전의 실행 횟수 증가 실패, 만료 갱신 뒤의 `.expired` 알림)가 사용자가 보기 전에 사라진다. Auth 상태 알림의 토큰 재조회는 로그아웃·만료 뒤에는 저장소를 읽지 않아 실패하지 않는다. 첫 값과 `.signedIn` 뒤에는 저장소를 읽으므로 드물게 직전 에러를 "토큰 읽기 실패" 로 덮을 수 있고, 이 한계를 코드 주석에 남겼다 (R2-3, R3-1) |
| R-D3 | AuthDemo 의 `perform` 은 결과를 쓰기 전에 시작할 때 잡은 세션이 현재 세션인지(`===`) 확인하고, 다르면 버린다. `observeStates` 도 같다 (R1-3) | 저장소를 바꾼 뒤 이전 세션의 토큰·에러가 새 세션 화면에 섞이지 않게 한다 |
| R-D4 | 서버 모드는 Picker 변경 때 보내지 않고 `refresh()` 가 갱신 직전에 `await server.setMode(serverMode)` 로 맞춘다. `refresh()` 는 `isRefreshing` 으로 한 번에 하나만 실행하고, 그동안 화면은 갱신 버튼을 막는다 (R1-4, R2-2) | 서버가 모드를 쓰는 곳은 갱신뿐이다. 변경마다 `Task` 를 만들면 도착 순서가 보장되지 않는다. `setMode` 를 부르는 곳이 `refresh()` 하나이므로 직렬화하면 모드 설정과 서버 응답 사이에 다른 모드가 끼어들 수 없다. 요청 단위로 모드를 넘기는 큐는 쓰지 않는다. `AuthSession` 이 진행 중인 갱신을 공유해 `server.refresh` 가 불리지 않는 호출이 생기면 큐가 어긋난다 |
| R-D5 | NavigationDemo 는 `.sheet`·`.fullScreenCover` 를 한 뷰에 두고, 바인딩의 `set(false)` 는 현재 스타일이 같을 때만 `dismiss()` 를 부른다 (R1-5) | 스타일 교체가 시뮬레이터에서 동작하는 것을 확인했다(sheet 안에서 fullScreenCover 로 교체 → 교체 후 dismiss). 계획 검증 목록에 시나리오를 추가했다 |
